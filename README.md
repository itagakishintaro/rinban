# Rinban(輪番)

朝会の司会や読書会の担当など、メンバーが交代で順番に担当する「輪番」を管理するWebアプリ。

## 機能

- **ログイン不要** — アカウント登録なしですぐ使える
- **URL共有だけで利用開始** — グループ作成時に発行されるURLをメンバーに共有するだけ
- **メンバー管理** — メンバーの追加・変更・削除
- **柔軟なローテーション設定** — 毎日 / 毎週 / 毎月第N曜日 / 毎年 / 毎週平日 をGoogle Calendar方式(開始日から選択肢を自動導出)で設定・変更できる
- **順序の管理** — 輪番の順序を設定・変更できる
- **スキップ・入れ替え** — 都合が悪いときに、その1ローテーションだけ他の人と順番を入れ替えられる
- **メール通知**(MVP後に実装) — メールを登録すると、指定タイミング(前日・1時間前など)に通知。オフにもできる。送信サービスは未選定(Resend等を候補に後続Issueで決定)

## アクセス制御

認証は行わない。グループ作成時に推測不能なランダムIDを含むURLを1つ発行し、
**URLを知っている人は誰でも閲覧・編集できる**。チーム内での共有利用を想定したシンプルな設計。

## 技術スタック

| 分類 | 技術 |
| --- | --- |
| フロントエンド | React 19 + Vite + TypeScript + Tailwind CSS 4 |
| バックエンド / DB | Firebase(Firestore, Hosting)完全サーバーレス・従量課金(Blazeプラン) |
| ユニットテスト | Vitest |
| 振る舞いテスト(BDD) | Gherkin(.feature、日本語)+ playwright-bdd + Playwright |
| CI/CD | GitHub Actions(PRでlint/テスト、mainマージでHosting自動デプロイ) |

## プロジェクト開始プロンプト

このプロジェクトは以下の指示から開始した。他プロジェクトの雛形としても利用できる。

```markdown
<目的>
朝会の司会や読書会の担当など、メンバーが交代で順番に担当する「輪番」を
管理するWebアプリを開発する。
</目的>

<機能要件>
- ログインなしで使える(認証を実装しない)
- グループ作成時に発行されるURLを共有するだけで閲覧・利用できる
- メンバーを追加・変更・削除できる
- ローテーションの周期を設定・変更できる(毎週◯曜日、毎月◯日、隔週など)
- 輪番の順序を設定・変更できる
- 都合が悪いとき、その1ローテーションに限って他のメンバーと順番を入れ替えられる
- メールアドレスを登録すると、指定タイミング(前日・1時間前など)に通知が届く。
  通知はオフにもできる
</機能要件>

<制約>
- インフラはFirebase + Firestoreで完全サーバーレス・従量課金とする
- ソースコードはGitHubで管理し、個人アカウント(itagaki.shintaro@gmail.com)を用いる。
  既存プロジェクト /Users/shintaro.itagaki/dev/run のアカウント設定・技術構成を参照する
</制約>

<進め方のルール>
- 不明点は推測せず、必ず質問して確認してから作業を進める
- ステップバイステップで進め、作業単位ごとにユーザーのレビューを受けて
  コミットしてから次に進む
- テスト駆動開発とする: 仕様を確認し、BDDで振る舞いテストを書き、
  TDDでユニットテストを書き、プロダクションコードを実装してテストを通す
- チケット駆動とする: 作業ごとにGitHub Issueを作成し、descriptionに作業内容、
  コメントに実装計画を記載する
- PRには、ユーザーがレビューすべき内容(変更点・確認手順・判断を仰ぎたい点)を明記する
</進め方のルール>

<作業手順>
1. 全体設計を行い、設計書をファイルに保存してレビューを受ける
2. アーキテクチャとアプリケーション構成を確定し、アプリケーションの骨格をつくる
3. MVPを作成し、機能を1つずつ追加していく
</作業手順>

<開発準備>
- 最初にAGENTS.md / README.md / DEVELOPMENT.mdを作成し、AI駆動開発の土台を構築する
- AGENTS.mdは常時読み込むグラウンドルールとし、「Xの場合にYを参照する」形の
  参照マップで必要な情報だけをオンデマンドに読み込める構成にする
- コンテキストエンジニアリング・ハーネスエンジニアリングの観点で必要な事項
  (テスト戦略、CI/CD、hook、権限設定など)を検討し、選択肢を提示してユーザーに確認する
</開発準備>
```
